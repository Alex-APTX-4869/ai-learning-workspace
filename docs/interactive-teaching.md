# 交互讲师与提示词优化

## 设计判断

“你将学到”难读不完全是提示词问题：此前界面直接展示知识点简介，简介同时承担目标、背景和范围说明。现在将简短 `learning_goals` 与正文 `lesson_cards` 分开，界面逐条展示目标，过长可展开。

知识点不是越小越好。一个知识点应围绕一个主要概念或可检验能力，可以有必要解释步骤；只有能够独立学习、独立检验的能力才应拆成另一个知识点。提示词与审查帮助控制粒度，但不能保证模型必然做出最优划分，也不会自动重排用户既有知识点。

不增加每页一个新的生成 Agent：内容制作阶段已经形成有顺序的卡片；“下一张”只是读取已审核内容，不调用模型。讲师只处理追问及明确的继续意图，沿用当前配置的模型供应商。

## 已优化的职责

| 节点 | 调整 |
| --- | --- |
| 需求深度 | 移除示例题数的锚定，根据关键未知量决定三档；仍遵守现有访谈预算 |
| 逐题访谈 | 检查语义重复、匹配学习基础；事实型问题的推荐不能冒充用户事实 |
| 选项解释 | 保留独立解释职责，不替用户作答、不推进访谈 |
| 需求归纳 | 简介只概括对象、目标和路径，详细约束归入专用字段 |
| 大纲与知识点 | 已确认需求为主要依据；先修顺序、单点目标、短简介；规则和用户数据分角色传入 |
| 小节规划 | 明确职责与必要复习；先修 ID 必须是更早的知识点，后端拒绝倒置依赖 |
| 讲解 | 直接生成可阅读的顺序卡片，而非写作提纲；每卡一个解释步骤 |
| 示例、练习、实验 | 按需调用；后续作者看到前面已写的材料，分别展示推理、检验理解、执行验证 |
| 审查与修订 | 只因实质问题拒绝，最多一次修订；保留合格部分；修订也只生成一份卡片正文 |
| 讲师 | 当前卡片答疑、少量必要补充、明确继续后请求下一张，不重写课程、不伪造掌握或执行结果 |

章节、小节、知识点和卡片不设凑数目标。学习目标最多 4 条、每卡正文最多 2400 字符是页面密度与接口边界，不是要求填满，也不是对课程教学规模设限。

## 学习顺序与操作

内容生成通过审查 → 开始或恢复带学 → 讲解卡片 → 可选示例 → 可选练习 → 可选代码实验。

- 每次推进一张内容卡，已看卡片和追问保留在同一对话列。右侧主体共用外层滚动区，卡片不再设置内部纵向滚动；按钮提供上一张、下一张，未提交练习可以明确跳过。
- 提问默认停留当前卡；“好”、疑问句、否定句不会触发翻页。
- 明确说“没有问题，继续”时，讲师可以返回 `show_next_card`，程序验证后最多推进一张。
- 题型独立为选择题、判断题、解答题，不要求每次三类齐全。选择题比较具体答案，不能用正误组合充当选项；判断题只显示正确/错误，不带字母编号；解答题不带选项。
- 客观题由后端按答案判定，提交后才显示参考答案和解析；解答题给参考思路，不以字符串匹配伪造分数。
- 看完当前知识点后可打开本小节的下一个知识点；最后一张不会擅自跳转课程。
- 可以切换“自主阅读”，直接阅读同源讲义、示例、练习和代码实验。

## 上下文与可靠性

讲师收到课程信息、已确认需求档案、当前知识点分工、目标、当前卡片、最近两张卡片、前后标题，以及最近 12 轮已完成答疑。历史每条用户文本、回复分别截到 2000、3000 字符；这是有界上下文，不声称无限记忆。练习未提交时不传标准答案与正确选项标记；没有浏览器实际运行信息时，讲师不得声称执行过代码。

版本化讲师会话按不可变内容版本保存当前卡片、阅读结束状态和作答；操作记录保存操作编号、用户问题、回复与状态。读取时恢复卡片与消息时间线，最多展示最近 200 个操作对应历史，并明确标出截断。阅读结束只表示浏览完成，不代表已掌握。新生成版本有独立进度，不把旧版位置套到新卡片上。

每个操作携带请求 UUID、当前卡片 ID 和 revision。重复请求去重；旧 revision 返回冲突后同步，不重复翻页或调用模型。答疑在后台运行，离开页面只停止轮询；重新进入恢复记录。网络结果不明时用原 UUID 重试。

课程内容生成也保留启动时的上下文快照，不因其他知识点新生成了摘要而使当前任务误判过期；课程结构、需求或当前选中内容变化仍会阻止旧结果覆盖。

## 当前边界与验证

- 文字对话已接模型，但回答是完整返回后展示，并非逐 token 流式输出；普通翻卡立即展示。
- 后台已使用 PostgreSQL 持久队列和本地 worker，退出页面不取消；成功步骤从检查点复用。模型调用在重启瞬间结果不明时仍须保守处理，不能承诺供应商恰好调用一次。
- 当前是本地个人工作台，没有新增账户隔离、语音会话、长期学员记忆或自动资料检索。
- 原讲义不具备卡片时可自主阅读；重新生成内容后使用带学。未删除真实课程或伪造迁移结果。
- Python 编辑器草稿、运行记录不会自动持久化或自动发给讲师。所有模型审查只提供质量辅助，不代替真实执行与事实核验。

运行后端回归：`.venv/bin/python -m unittest discover -s backend/tests -q`。

运行前端组件与状态检查：在 `frontend/` 执行 `npm run test:learning`；检查安全 Markdown、目标列表、练习反馈、幂等重试、页面退出和版本冲突。执行 `npm run build` 检查 TypeScript 与生产构建。

测试使用隔离数据库与模型替身，不消耗真实模型配额，也不把测试内容插入真实课程。实际模型的教学质量仍需通过后续使用样本评估；提示词的约束不是质量已获证明的声明。

## 2026-09-09 内容质量修订

- 规划先辨别学习者已知与本点缺口，不把课程出现过某术语当成已经掌握。
- 作者围绕一个具体场景逐步解释输入、动作、结果和原因；一个卡片只解决一个主要疑问。必要微型例子属于讲解本身，不因未启用独立示例 Agent 而省略。
- 审查要求指出具体卡片和缺失推理步骤，修订实际补齐因果，而非只换通俗词。额外规则检查 Python/JSON 字面量混用及明显题型混用；语义审查仍可能遗漏问题。
- 讲师优先回答当前疑点，不把小问题扩成整套知识清单，不声称运行未执行代码。
- 提示词版本已更新，重新生成时不会命中旧规划缓存；已有正文保留，需用户重新生成才应用新规则。
