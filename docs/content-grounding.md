# 原文驱动内容：基础实现与验收（2026-09-13）

本轮只打通知识点内容制作的原文证据链。没有重新生成用户课程，也没有删除历史内容。大纲/知识点目录与资料的全面覆盖检查仍是下一阶段。

## 当前流程

1. 后台任务领取时，按当前目录版本已确认的文件、处理版本和页段检索原文。优先目标知识点关键词，无命中时尝试小节标题。
2. 最多保存 6 个去重片段，每段最多 1800 字符，包含文件名、物理页/段落、处理版本、原始字符偏移。快照写入任务 JSON；恢复和修订复用，不在普通页面读取时重新检索。
3. 讲解及可选内容作者读取这些片段。内容区分 source_based（原文支持的改写/应用）与 supplemental（补充），引用只能来自本次 S1–S6。
4. 零命中：停止，说明检索不到不代表原文一定不存在。作者报告阻碍当前主要目标的 source_gaps：保存不发布的候选，停止后续可选作者/审查/修订调用。范围外主题或明确自拟的辅助类比本身不算缺料。
5. 正常草稿经过语义审查；发布前程序再次验证引用编号、依据声明和资料缺口。错误引用、全部讲解无原文支撑或缺口未解决时不替换旧内容。
6. 原文元数据由程序写入内容版本，模型不能更改文件名、页码、快照。阅读和逐卡讲课都有“资料出处与补充说明”，点击回读原文。讲师答疑使用这个内容版本的同一证据快照，不假装动态检索过整份资料。

## 验收证据

- 最终回归：153 项后端测试、8 项资料前端检查、12 项学习前端检查、前端类型检查与正式构建通过。
- 后端覆盖：原文片段与偏移一致、长度限制、排除页不可进入、目录版本隔离、引用白名单、缺料不继续调用、保留旧内容、修订不能伪造来源。
- 前端：原文安全转义、旧响应不能串版本、原文关闭/重试/继续读取，以及引用与补充标签。学习模式原有状态检查继续执行。
- 真实缺料样例：`tmp/basic-live-grounding-ba43wc1x`。合成教材只含“HTTP 422 indicates validation failure”，不含具体 `/items/abc` 请求或响应细节。首轮按成功路径运行的断言失败，实际结果是 `needs_review`，旧内容未被替换；保留原始失败记录，不改写为成功日志。这暴露了缺料还尝试修订的浪费，随后增加作者报告缺料后直接停止的规则，并用隔离回归验证。
- 真实成功样例：`tmp/basic-live-grounding-nnnsra09`。生成已有目录中“说明 422 的基本含义”，使用 qwen3.6:27b，共 4 次调用：规划 55.59s、讲解 78.18s、审查 108.95s、讲师 7.52s。生成 3 张卡片，第一张有 S1 原文引用，另两张标注补充；可选示例/练习/代码实验本次未安排。原文回查与保存片段一致，排除的第 2 页没有进入。
- 浏览器在独立 8002/5175 预览实际验证：打开第二小节 → 讲课卡片 → 展开出处 → 点击文件第 1 页 → 读取原文 → 关闭回到同一对话 → 下一张只出现新卡片 → 补充卡片无伪造引用 → 退出恢复自主阅读。没有向预览提交新的模型请求。

这证明基础软件链路和本例来源定位可用，不代表教学质量或语义支撑率普遍达标。例如当前样例仍有“你已经认出”的学习状态假设、解释略泛等问题；审查模型也可能漏判。关键词检索对同义问法、跨页推理仍有限制。

## 重现

普通回归不调用模型：

```sh
.venv/bin/python -m unittest discover -s backend/tests -q
cd frontend
npm run test:materials
npm run test:learning
npm run build
```

真实模型验收必须显式选择，可能消耗额度；每次最多 10 次调用。脚本仅复制固定合成验收数据库和资料，不接受任意生产库路径，也不修改原验收数据。

```sh
.venv/bin/python scripts/accept_grounding_live.py --run-real-models --section-index 1
# 缺料保护样例（应停止并保留旧内容）
.venv/bin/python scripts/accept_grounding_live.py --run-real-models --section-index 0
```
