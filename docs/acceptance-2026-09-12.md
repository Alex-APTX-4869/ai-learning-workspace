# 2026-09-12：基础功能第一轮真实验收

## 结论

**抽样软件链路已跑通；不代表整个基础阶段、所有教材和教学质量全部验收通过。** 本轮没有开启高级检索、视觉识别或新增业务框架。

用学校已配置的 `qwen3.6:27b`，在独立 SQLite 中真实执行：合成 PDF 上传与解析 → 资料分析 → 需求访谈与确认 → 流式目录 → 一章知识点 → 一个知识点的讲解/示例 → 内容审查、一次修订与复审 → 讲师答疑。没有向已有课程写入测试数据，也没有上传私人文件。

## 证据

结果目录：`tmp/basic-live-gdoec1vl/`。

- 主流程 14 次真实调用，另有目录/需求总结对照 2 次、示例/练习组件抽样 2 次，共 18 次；本轮都获得响应，没有遇到 502。
- 单次耗时 9.23–104.71 秒；所有调用累计 1041.27 秒，不等于整轮墙钟耗时。16 次非流调用报告了共 117688 tokens，另两次流式输出未记录用量；无定价信息，不据此推算费用。
- `result.json` 为 `software_flow_passed`，质量评价单独记录在本文，不能用 JSON 结构校验代替。
- 后端 146 项测试通过；前端 12 项学习检查、7 项资料检查通过；类型检查与正式构建通过。

## 下一步仍留在基础质量阶段

1. 用改进后的完整小节再测“讲解 → 有增量的示例 → 课程内练习”，避免仅重测各组件而误认为整体已合格。
2. 检查必要基础解释与跨知识点分工，防止为避重复而反复推迟解释；改善干扰选项质量。
3. 定位访谈/内容制作的长等待，分别评估请求耗时、输出量与工作流调用次数。单次样本不能断言模型“太差”，也不能保证换模型或关闭某种推理配置一定改善。
4. 基础质量稳定后，才进入讲师按需查资料及后续章节增补功能。代码实验、扫描件、公式/图表、混合检索不在本轮通过范围。
