# 璃云白 · 个人 AI 学习工作台

本文记录当前实现及既有边界。2026-09-08 收束的后续需求见 [资料驱动课程完整方案](materials-platform-plan.md) 与 [实施里程碑](implementation-milestones.md)；非破坏性版本、多模型路由已落地，资料上传/标注/索引仍待实施，不应将设计当成现有能力。

## 已确认的产品方向

- 个人使用，暂不做账号、权限和多用户。
- 每门课程是一张可进入的卡片；课程内部展示章节、小节。
- 先生成章节和小节，再按章生成知识点。生成成功自动保存。
- 点击小节，打开学习弹窗：左侧知识点列表，右侧当前知识点的内容。
- 内容制作采用“规划者 → 讲解 Agent → 按需专项 Agent → 审查者”；先规划同一小节的教学分工，再按知识点制作内容。
- 讲解是必有内容；示例、练习和 Python 代码实验由规划 Agent 根据教学目标按需路由，界面只显示实际存在的模块。
- 每门课程可拥有参考资料库。引用必须可追溯；允许扩展，扩展部分标为“AI 补充”。
- 璃云白主题：冷白背景、白色面板、深灰文字、克制的雾蓝强调色。
- 创建课程前由一个需求确认 Agent 动态访谈；内部使用“需求分析 → 逐题访谈 → 需求归纳”的受限工作流，最终需求档案必须由用户确认。

## 依赖规则

页面 → 功能组件/状态 → 功能 API → 共享请求函数。

后端路由 → 业务服务 → 数据库/AI 客户端。提示词不放路由中。AI 不直接写数据库，校验后的结果由课程业务服务保存。前端只保存显示状态，数据库保存课程内容。首页只加载课程摘要；进入课程才获取完整目录。知识点正文加入后继续按点加载。

同一数据类型只有一个定义位置；组件通过参数接收数据，通过事件通知操作。单个文件若同时处理布局、网络、数据整理和提示词，优先按职责拆分，而不是按行数机械切割。

## 模型接入与安全边界

- 当前接入边界是 **OpenAI-compatible API**：用户可配置服务名称、Base URL、模型名和 API key，但底层仍使用 OpenAI 消息与流式协议。仅修改 URL 不能把原生 Anthropic、Gemini 等不同协议变成兼容接口；以后若支持它们，应增加独立 adapter，而不是宣称支持任意协议。
- 已保存供应商的 API key 只写入操作系统钥匙串。数据库 `llm_providers` 只保存随机 `key_ref` 和非敏感元数据；读取接口只返回是否已配置，不回传密钥。项目根目录 `.env` 仍可作为已有 NUS 配置的兼容回退。
- `api_key` 使用敏感类型，FastAPI 的 422 校验响应会删除 `input`/`ctx` 等可能含原请求的字段，并对 URL 内嵌凭据脱敏。Base URL 不允许用户名、密码、查询参数或片段；远程地址要求 HTTPS，本机回环服务可使用 HTTP。
- 这是本机个人工作台的信任边界，不是多租户密钥托管服务。若以后对公网开放，还需补身份认证、用户级配置隔离、SSRF/重定向防护、调用额度和密钥轮换策略。

## 大纲数量、流式与保存边界

- 产品不为章节或小节设置教学数量上限，也不在界面或提示词中暗示固定数量；模型应根据 CourseBrief、内容范围和教学顺序自行决定。结构仍要求至少一个章节、每章至少一个小节，空大纲不会保存。
- “不限制教学数量”不等于无限计算资源。模型上下文窗口、输出窗口、请求超时、内存和数据库容量仍是客观边界。流被截断、协议错误或最终结构校验失败时整次失败，不静默删减，也不把半份大纲写入数据库；超大课程后续应采用分批生成，而不是引入一个伪装成教学规则的固定章数。
- 大纲生成使用模型的真实 token 流。后端把不稳定的 token 块缓冲成逐行 NDJSON，只向前端发布完整的 `chapter`、`section` 等事件；这些事件用于即时预览，不代表已经保存。
- 只有收到唯一的 `done`、全部 NDJSON 可解析且完整大纲通过结构校验后，后端才在事务中保存新版本。断流、超时、错误或用户中止均不保存部分版本。这里采用的是“真 token 流 + 经校验的领域事件”，不是定时器模拟的阶段动画，也不让前端直接解析半截 JSON。

## 大纲版本与课程内容边界

- 每次生成可带本次 `additional_requirements`，也可明确选择一个本课程旧版本作为 `reference_outline`；默认不参考。旧版只是次要参考，不能覆盖当前课程信息和 CourseBrief。
- 对通过需求确认创建的课程，已确认 CourseBrief 始终放入生成上下文并作为课程设计的主要依据。附加要求只描述本次变化，旧版只用于继承或改进。为兼容早期直接创建的课程，确实没有确认档案时会显式传入 `course_brief: null` 并回退到现有课程名称和简介，不制造模拟 Brief。
- 当前 MVP 的版本是不可变的 **outline JSON 快照**，而现有 `Course → Chapter → Section → Point` 仍是供旧接口和学习界面读取的唯一物化树。首次启用版本时会先把可校验的旧目录保存为 V1；选中版本时再把快照安全物化到这棵树。
- 当物化树还没有知识点或讲义时，可以切换版本并替换纯目录结构；一旦任一小节已有知识点或讲义，后端返回冲突并阻止切换，避免级联关系删除学习成果。因此当前界面中的“版本不会删除知识点”含义是拒绝危险操作，不是所有版本都已拥有独立知识内容。
- 每个版本拥有完整 Chapter/Section/Point 内容树、可在任意版本间无损切换，属于后续数据模型升级；实现前不得用标题匹配、移动现有节点或隐式复制来假装完成。

## 侧栏课程列表取舍

侧栏课程列表采用 `max-height: min(34dvh, 280px)` 和内部纵向滚动，而不是预留固定高度：课程少时不留下大块空白，课程多时也不会把底部个人区域推出视口。课程名保持单行省略并通过标题提示查看全名；移动端隐藏这组次级入口。若以后要求固定的是“每个课程行”的高度，应单独约束行高，不要把列表容器的最大高度误当成固定行高。

## 当前实施边界

当前已交付课程管理界面、学习弹窗、后端模块化、需求确认 Agent、OpenAI-compatible 模型配置、NDJSON 真流大纲预览、大纲快照版本，以及知识点的“规划 → 讲解 → 按需专项 Agent → 审查 → 有限修订”内容工作流。新建课程通过需求确认流程；其最终 CourseBrief 持久化保存并在课程内的“课程信息”中展示。编辑已有课程仍使用普通表单。

资料上传与可追溯引用属于后续阶段。当前知识点 Agent 会生成简短学习目标与逐步讲解卡片，并按需调用示例、练习和代码实验 Agent；通过审查后才切换为当前可读版本。代码实验已能在浏览器 Web Worker 内真实执行 Python 并返回断言结果，不会在 FastAPI 主进程执行用户代码。尚无资料时不显示虚构引用。

交互讲师已接入：一张卡片一个阅读步骤，按讲解、示例、练习、代码实验推进；没有的阶段自动跳过。按钮翻页不调用模型，用户提问才触发讲师。讲师的 `show_next_card` 仅是受限动作意图，由后端按明确用户确认、当前卡片及会话版本执行，模型不直接写进度。具体取舍见 [interactive-teaching.md](interactive-teaching.md)。

生成任务与学习弹窗的生命周期已解耦：关闭弹窗或离开页面只停止本地轮询，后端继续执行；再次打开该知识点时查询并恢复活动任务。用户显式点击“停止生成”才把任务设为 `cancelled`，之后返回的在途模型结果不会被保存。但当前仍使用 FastAPI 进程内 `BackgroundTasks`；如后端进程重启，旧任务会标记失败而不会自动续跑。跨进程可恢复需要外部任务队列。

生成中的错误不清除既有内容；不同课程的请求按课程 ID 归属。大纲可生成多个独立快照，但完整学习内容尚未按版本拆分；已有知识点或讲义时以拒绝破坏性切换保证安全。原项目已有环境配置、虚拟环境、JavaScript 备份保留。
