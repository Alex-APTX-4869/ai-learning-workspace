每阶段完成一条可验证路径，再进入依赖它的下一阶段。先底层版本和任务，再接多模型、资料，再接用户流程；不先制作能点击但无法真实处理文件的模拟页面。

## 当前执行范围：基础版本优先（2026-09-12）

按用户最新要求，先验收“上传 → 本地文字解析 → 范围确认 → 资料分析/需求确认 → 课程关联 → 关键词搜索 → 原文读取”，暂不继续扩大视觉、公式、图表或向量检索功能。未接入的视觉识别代码及未应用迁移已撤出；正式数据库仍保持 `20260909_04_intake_extensions`。

基础闭环新增 `test_material_basic_flow.py`：真实上传并解析合成 PDF/DOCX、确认文字范围、通过正式接口创建课程、重复确认不重复建课、搜索并读取原文、核对原文件及 PDF 原页。模型节点使用隔离替身，因此只能证明软件流程与数据衔接，不能证明真实模型的识别/摘要/教学质量。只有已验收的基础流程稳定后，再逐项启用高级功能；M3—M6 未完成项仍保留，不提前勾选。

2026-09-12 后续完成第一轮真实模型抽样：18 次 NUS 调用，资料分析到讲师答疑的软件链路通过；目录粒度、需求范围归纳与两处页面显示已改进。146 项后端测试、19 项前端检查与构建通过。示例增量、题目质量与长等待仍待改进，不能把基础质量阶段整体勾选完成。具体证据和边界见 [当日真实验收记录](acceptance-2026-09-12.md)。

## 首批可见交付与范围控制

M1 首先解决旧版本能否安全保留；M2 提供可操作的多模型分配；M3 才开放真实上传/标注与解析报告。M4 形成第一条“上传 → 访谈 → 有依据的大纲”闭环，M5 完成局部编辑，M6 完成讲师查资料闭环。

首版不承诺：任意厂商原生协议自动兼容、全部复杂公式百分之百识别、无限文件大小、永久零重复计费、自动联网补教材。遇到能力缺项必须明确提示，不用隐藏降级掩盖。

只有每阶段退出条件有测试证据，才勾选完成。暂不预估具体天数：文档样本、模型能力与本机兼容性尚未验证，先完成 M1 的设计落地与 M3 的小规模解析验证，再估后续工作量。

## 贯穿验收：用同一门课程走完闭环

这是一组待执行的验收场景，不是本轮已跑通的结果。

1. 创建时上传总述和前三章资料，声明“本批部分”；处理完资料再访谈，拒绝一条 AI 补章建议。在草稿中完成这三章的知识点结构后发布 O1，不能出现被拒绝主题或未上传部分的虚构正文。
2. 为 O1 中一个已有知识点制作正文并开始学习；关闭弹窗后任务继续，重新打开仍定位到正确内容版本和学习进度。
3. 后续主动新增第 4 章并上传其资料，确认发布 O2。O1 仍只有前三章，旧章内容不被重写。
4. 在 O2 的一个既有知识点补一张图，只重写讲解并采用 C2。O1 仍选择 C1，旧会话不混入 C2；其他知识点也不能自动使用这张点级补图。
5. 在 O2 的 C2 中问讲师图表含义，能打开相应依据；回到 O1 答疑，检索不到这张新图。向量服务不可用时报告降级，指定原页仍可读取。
6. 再开一次目录草稿，同时更改模型默认、重启工作进程并模拟重复提交。检查已完成步骤不丢、原任务模型分配不变、不会重复发布；外部调用结果不明时要求核对而非盲目重试。
