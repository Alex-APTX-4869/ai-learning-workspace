# 内容制作与资料库实施方案

本文保留此前实施过程。下一阶段的资料格式、版本与局部编辑规则以 [资料驱动课程完整方案](materials-platform-plan.md) 为准：资料核心范围已更新为 PDF、Word、公式和图表；实施顺序见 [里程碑](implementation-milestones.md)。下文旧的“先仅文字资料”等设想不是本轮最终范围。

## 阶段顺序

1. 课程管理与保存：卡片、章节目录、小节学习弹窗、稳定数据库 ID。
2. 课程资料库：上传、提取、按段索引、检索、显示可定位的原文。
3. 小节教学规划：围绕全课程范围，约定每个知识点的目标、范围、先修和示例。
4. 知识点内容制作：按需写作、审查、有限修订、保存和阅读。
5. Python 练习与 AI 辅导：独立执行环境、运行结果、学习问答。
6. 后台任务、恢复与进度：可重试、可取消、流式展示、内容版本及学习进度。

阶段 3—4 的长调用开始时就要引入持久化任务状态；阶段 6 完善体验，不把任务可靠性拖到最后。

当前进度：阶段 1、3、4 已实现；阶段 4 的任务状态、幂等、有限修订和内容版本也已同步落地。阶段 5 已有浏览器内 Python 实验与逐卡交互讲师；阶段 6 已支持内容生成离开页面后恢复，以及学习进度、作答和对话保存。阶段 2、代码运行结果自动传给讲师、真正的外部任务队列及进程重启后续跑仍未实现。

## 资料如何进入课程

前端先支持文字版 PDF、Markdown、TXT。扫描文件需要 OCR（文字识别），首版明确提示暂不支持；不默默把空文本标成导入成功。

`保存原文件 → 提取文字及位置 → 按标题和段落切分 → 保存索引 → 标记可使用`

- 原文件保存在应用的数据目录，使用生成的文件 ID 作为存储名称。
- `materials` 存课程 ID、原名称、类型、文件摘要、版本、状态及错误。
- `material_chunks` 存文件 ID、片段 ID、标题、页码/段落位置和文本。
- `search_course_materials(course_id, query)` 只检索本课程的已就绪资料。
- 先实现可测试的关键词检索；语义检索需确认 NUS 是否提供嵌入模型，否则选择本地模型。不能假定聊天模型能生成向量。可在现有 PostgreSQL 上评估 pgvector。
- 规划使用目录和分层摘要把握全貌，作者使用相关原文片段。长资料按层概括，不一次塞入所有正文。
- 上传文本作为参考数据，不具有修改系统任务、调用工具或泄露配置的权限。

更新资料后，标记引用旧版本的内容“资料已更新”；保留原引用版本。用户删除资料前要明确告知哪些内容会失去来源访问，不连带删除已生成讲义。

## 按需内容制作角色

| 角色 | 输入 | 输出 |
| --- | --- | --- |
| 规划者 `plan_section()` | 课程目标、全课程范围、当前小节知识点、已有内容摘要 | 每点的目标与分工，并分别决定是否需要示例、练习、代码实验 |
| 讲解 Agent `write_lesson()` | 当前规划、同小节分工、相关内容摘要 | 简短学习目标、顺序讲解卡片与摘要；阅读正文由卡片组合 |
| 示例 Agent `write_examples()` | 规划中的示例目标、讲解草稿 | 只在需要时生成的示例 |
| 练习 Agent `write_exercises()` | 检验目标、讲解与已生成示例 | 优先单选和判断，检验迁移和误解，需要时才用多选或陈述题 |
| 代码实验 Agent `write_code_lab()` | 编程目标、讲解、已有示例与练习 | 可在纯 Python 浏览器环境运行的说明、起始代码、参考实现和断言测试 |
| 审查者 `review_point()` | 合并草稿、规划、可能重复的相关内容 | 是否通过、具体问题、需要局部修改的块 |

这些是职责分离的节点，可以使用同一个 NUS 模型，不是多个常驻进程。规划者是路由节点：三个可选 Agent 只在对应 `needed=true` 时调用，避免为凑页面模块增加内容和请求。

## 一次内容请求

1. 用户点击知识点。已有可用内容直接返回。
2. `get_or_create_job(point_id, plan_version)` 防止重复点击产生重复任务。
3. `build_point_context()` 读取规划、先修摘要、相邻范围、相关原文。已生成不等于用户已学会。
4. 讲解 Agent 生成必有正文；工作流根据规划结果按需调用示例、练习和代码实验 Agent，再组合为结构化内容。
5. 后端确认可选组件的实际有无与规划决定完全一致；审查者再检查重复、范围、题型和代码实验的可执行性。
6. 当前最多一轮修订；二次审查仍不通过时保留候选版本并标记待检查，禁止无限循环。
7. 自动保存内容版本、覆盖摘要、引用及任务结果。失败不替换已有可用版本。

状态：`queued → planning → writing → reviewing → ready / needs_review / failed / cancelled`。同一小节最多一个活动任务；重复点击不会新建重复任务。关闭学习弹窗、切换知识点或离开路由只停止前端轮询，不修改后端任务；重新进入时通过活动任务接口恢复进度。只有用户点击“停止生成”才写入 `cancelled`。已经发给模型供应商的同步请求不一定能在网络层立刻撤回，但它返回后会被丢弃，不启动后续节点、不保存。

## 内容与引用

`point_plans` 保存教学规划与版本；`point_content_versions` 保存内容块和审核信息；`generation_jobs` 保存任务状态；`citations` 连接内容块与资料片段；`learning_progress` 单独记录用户完成状态。

内容块建议具有 `id`、`type`、`body`、`source_chunk_ids` 和 `origin`。`origin` 区分“资料依据”“AI 补充”，允许一个知识点混合两类内容。引用位置从资料记录解析，模型只能引用已有片段 ID。

练习答案默认折叠。审查同时关注无意义重讲、必要复习、进阶应用三种情况；不能依据相似度直接删除内容。有关联的小节可以共同推进同一个代码例子。

## Python 练习

首版已使用 Pyodide 在 Web Worker（后台线程）运行，用户可手动终止，且设置 8 秒运行限制和 12,000 字符输出上限。每次结束都销毁 Worker。它适合基础 Python，不支持完整 FastAPI 服务、数据库、服务端文件或任意外部包。需要真实服务端能力时，另行设计隔离容器；不在 FastAPI 主进程里执行用户代码。

实验包含说明、起始代码、参考实现和断言测试；运行结果由真实执行环境产生，不能由模型假装运行。当前是学习反馈而非防作弊评测环境。用户可在讲师对话中粘贴代码或实际错误提问；编辑器代码、运行输出不会自动上传给模型，也尚未保存到学习进度中。

## 可验收条件

- 上传资料后显示明确处理状态；引用能打开正确的原文件位置。
- 在 A 课程生成内容时不会检索到 B 课程的资料。
- 重复点击同一知识点不会重复创建活动任务。
- 生成失败不覆盖旧讲义，重试不会复制练习或知识点。
- 存在跨点重复的测试课程，能区分重讲和合理进阶；保留人工查看审查意见入口。
- 引用检查与模型内容审查分开测试；模型审查通过不意味着事实一定正确。
- 代码可以中止，输出有上限，实际运行结果与 AI 说明明确区分。
